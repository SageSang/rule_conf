# Sub-Store 节点处理

Sub-Store 只负责节点订阅的预处理。它不负责 OpenClash 的应用规则、策略组和默认出口；这些内容唯一维护在根目录的 [`meta.ini`](../meta.ini) 中。

## 处理链路

```text
多个节点订阅
    ↓
Sub-Store 合集
    ↓
节点筛选或整理脚本
    ↓
输出订阅
    ↓
OpenClash / Clash 使用 meta.ini 转换
```

## 脚本选择

| 脚本 | 类型 | 作用 | 是否修改节点对象 |
| --- | --- | --- | --- |
| [`keep-core-premium-and-remote.js`](operators/keep-core-premium-and-remote.js) | Script Filter 或 Script Operator | 删除五个核心国家的普通节点，只保留这些国家的 High 节点及其他地区节点 | Filter 模式不修改；Operator 模式只返回筛选结果 |
| [`filter-sort-by-region-and-quality.js`](operators/filter-sort-by-region-and-quality.js) | Script Operator | 删除说明项、按连接参数去重、处理重复名称并按地区和倍率排序 | 是，重复名称可能被添加序号 |

两个脚本可以按需要单独使用。若同时使用，先确定是否真的需要删除五个核心国家的普通节点，再使用整理排序脚本。

## 节点语义

五个核心国家是香港、台湾、美国、日本和新加坡。

High 节点只匹配严格大于 `1x` 或 `1倍` 的倍率，例如：

- 属于 High：`1.01x`、`1.5x`、`2x`、`15x`、`5倍消耗`。
- 不属于 High：`0.1x`、`0.5x`、`1x`、`1.0x`、`1.00x`、`1倍`。
- `进阶IEPL`、`专线`、`原生`、`家宽`、`星链` 等线路描述不单独构成 High 条件。

国家识别优先使用国旗、中文名称、英文全称和城市别名；两位 ISO 代码只识别大写完整单词。无法可靠识别的节点应保留，不能因为名称不标准而删除。

排序顺序为：

```text
香港 → 台湾 → 美国 → 日本 → 新加坡 → 韩国 → 加拿大 → 阿根廷
→ 英国 → 德国 → 法国 → 印度 → 马来西亚 → 土耳其 → 俄罗斯
→ 乌克兰 → 意大利 → 巴基斯坦 → 埃及 → 澳大利亚 → 南非
→ 冷门 → 其他
```

同一地区内，普通节点排在 High 节点之前；同一等级保留原订阅顺序。

## 使用方式

1. 在 Sub-Store 建立合集，加入需要合并的节点订阅。
2. 根据目标选择上表中的脚本类型和脚本文件。
3. 预览输出，确认说明项、重复节点和地区顺序符合预期。
4. 将输出订阅交给客户端或 OpenClash；不要在 Sub-Store 里复制 `meta.ini` 的应用分流逻辑。

不要把 JavaScript 粘贴到普通的正则过滤或正则删除操作中。若出现“保留节点 0”，优先检查脚本类型是否选错，以及是否粘贴了完整脚本内容。

不要额外添加全局 `0.1x`、`福利` 等删除规则。这样会改变当前约定的节点范围，并可能删除本应保留的普通节点。
