# 配置策略

本文档记录 `meta.ini` 的稳定设计原则。它描述“为什么这样维护”，不复制完整的策略组选项和正则表达式；具体行为以 [`meta.ini`](../meta.ini) 为准。

## 规则优先级

`meta.ini` 的 `ruleset` 按从上到下的顺序匹配。规则排列遵循以下原则：

1. 私网和明确的直连规则先处理。
2. 需要独立出口的应用规则必须早于中国直连规则。
3. 应用专属规则必须早于对应的通用类别规则。
4. GFW、非标端口和 `FINAL` 只承担兜底职责。

当前具有专属规则的重点场景包括 AI、Google FCM、日本原生解锁、Reddit、游戏平台、BT/PT、交易所、Google Voice 和 Microsoft 等。

## 策略组模型

### 五个核心国家

香港、台湾、美国、日本、新加坡各自拥有：

- 一个普通节点组；
- 一个 High 节点组；
- 对应的应用策略组选项。

应用策略组中，核心国家始终按照“普通 → 同国家 High”相邻排列。这样既保留普通出口，也能在面板中快速切换到高倍率出口。

### 其他国家

韩国、加拿大、阿根廷、英国、德国、法国、印度、马来西亚、土耳其、俄罗斯、乌克兰、意大利、巴基斯坦、埃及、澳大利亚和南非各自保留完整节点组，不参与五个核心国家的 High 排除逻辑。

### 冷门节点

`🧊 冷门节点` 是独立国家组的补集：未命中这些国家组的节点都应保留在这里。它用于承接新国家、供应商自定义名称和无法可靠识别的节点。

这是一个保守策略：宁可把未知节点留在冷门组，也不要通过猜测性正则将节点分错国家或删除。

## High 倍率定义

High 只匹配数值严格大于 `1x` 或 `1倍` 的标签。

| 名称示例 | 归类 |
| --- | --- |
| `1.01x`、`1.5x`、`2x`、`15x`、`5倍消耗` | High |
| `0.1x`、`0.5x`、`1x`、`1.0x`、`1.00x`、`1倍` | 普通 |
| `专线`、`原生`、`家宽`、`IEPL`、`IPLC`、`星链` | 不单独决定倍率 |

Sub-Store 和 `meta.ini` 必须使用同一套含义。不要在订阅过滤层增加全局 `0.1x` 或“福利”删除条件。

## 国家名称匹配

- 国旗、中文国家名、英文全称和明确城市名可以忽略大小写匹配。
- 两位 ISO 代码必须是大写完整单词，例如 `(?-i:\bUS\b)`。
- 禁止使用裸 `US`、`IN` 等片段。
- `India` 与 `Indonesia` 必须区分。
- 交通单位、普通英文单词和国家代码重合时，应优先避免误匹配。

## 默认值和展示顺序

- `select` 策略组的第一个选项就是默认值。
- 任何调整默认值都直接修改 `meta.ini` 的第一个选项。
- 应用组的展示顺序影响面板选择体验，但不改变规则命中顺序。
- 默认值的完整清单不在文档中重复维护，避免文档和配置发生漂移。

## 职责边界

- 应用分流和出口选择：`meta.ini`。
- 节点过滤、去重、重命名和排序：`sub-store/operators/`。
- 本地 SOCKS 端口转换：`tools/`。
- 规则源说明、运维步骤和历史原因：`docs/` 与 `CHANGELOG.md`。
