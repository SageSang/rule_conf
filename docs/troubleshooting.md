# 故障排查

本文档记录两个维护会话中已经出现过的典型问题，以及它们对应的处理方向。

## 策略组选项被拼接

**现象：** 生成配置中出现多个国家组连成一个异常名称，或策略组选择项不完整。

**原因：** `custom_proxy_group` 的反引号分隔符缺失或位置错误。

**处理：** 检查受影响行的组名、类型、正则、测速 URL 和选项分隔符。不要只修改生成后的 YAML，必须修复 `meta.ini`。

## 国家误匹配

**现象：** Australia 被归入美国，Singapore 被归入印度，或包含普通英文单词的节点被分到错误国家。

**原因：** 使用了裸的 `US`、`IN` 等字符串，或者在忽略大小写的外层正则中没有保护大写 ISO 代码。

**处理：** 两位 ISO 代码使用大写完整单词，例如 `(?-i:\bUS\b)`；国家全称和城市别名保持明确，印度和印度尼西亚必须区分。

## High 节点分类不一致

**现象：** Sub-Store 和 OpenClash 对同一个节点的普通/High 判断不同。

**原因：** 一处使用倍率数值，另一处使用“专线、原生、IEPL”等线路词，或把 `1x` / `1倍` 错认为 High。

**处理：** 统一采用严格大于 `1x` 或 `1倍` 的定义。`0.1x`、`0.5x`、`1x`、`1.0x`、`1.00x` 和 `1倍` 都属于普通节点。

## Sub-Store 保留节点为 0

**现象：** 运行脚本后所有节点都被删除，显示“保留节点 0”。

**原因：** 把脚本粘贴到了普通正则过滤操作，或将 Script Filter 与 Script Operator 的入口类型混用。

**处理：** 删除错误的旧操作，重新添加 Script Filter 或 Script Operator，再粘贴完整脚本。具体脚本选择见 [sub-store/README.md](../sub-store/README.md)。

## 节点被错误删除

**现象：** 供应商自定义名称、冷门国家或未知地区节点消失。

**原因：** 使用了过宽的国家正则或全局 `0.1x`、`福利` 删除规则。

**处理：** 未知国家应保留到冷门或其他；不要在 Sub-Store 额外添加全局删除条件。

## 生成结果仍是旧配置

**现象：** GitHub 上的 `meta.ini` 已修改，但远程 SubConverter 生成结果仍包含旧策略组或旧正则。

**原因：** 模板服务或中间订阅缓存了旧版本。

**处理：** 确认客户端使用的模板地址，清理或等待缓存失效；对需要稳定发布的版本，可以使用固定的 Git Commit 版本作为模板引用，避免分支内容变化和缓存同时造成误判。

## 本地 SOCKS 与透明代理冲突

**现象：** 本地 SOCKS 出口无法连接、请求循环回 OpenClash，或切换代理栈后网络异常。

**原因：** 本地 SOCKS 进程、OpenClash、HomeProxy 或 sing-box 同时接管相同的透明代理、DNS 或端口。

**处理：** 将本地 SOCKS 作为独立链路检查，确认监听端口、进程用户和路由器当前运行的代理栈；不要通过修改 `meta.ini` 来解决进程或端口冲突。
